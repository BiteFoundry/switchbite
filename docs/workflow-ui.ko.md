# 로컬 워크플로 화면

`switchbite workflow app`을 실행하고 표시된 주소를 엽니다. 기본 주소는 `http://127.0.0.1:58420/`입니다.

화면은 승인된 Work in motion 목업을 실제 워크플로 API에 연결한 구성입니다. 왼쪽에서 작업과 도구를 설정하고, 오른쪽에서 작업 그래프와 작업자별 출력을 확인합니다.

[2026-10-28 로컬 적용·검증 기록](work-in-motion-live-validation-2026-10-28.json).

1. 감지된 AI 도구 목록에서 이번 작업에 사용할 도구를 선택합니다. 각 도구의 모델 수와 확인된 연결 상태를 함께 표시합니다. 선택은 자동으로 저장되며, **도구 다시 찾기**로 목록을 갱신할 수 있습니다.
2. 커밋이 있는 Git 프로젝트의 절대 경로와 작업 목표, 완료 조건을 입력합니다.
3. 조율자 모델과 동시 작업 수를 고르고 **작업 시작**을 누릅니다. 동시 작업 수는 기본 3개이며 1~16개로 설정합니다. 도구를 하나 이상 선택해야 시작할 수 있습니다. 기존 CLI 로그인으로 새 작업 세션을 실행합니다.
4. 조율자가 작업 계획을 만들고, Jev 또는 설정한 판단기가 허용된 도구에 모델을 배정합니다. 독립 작업은 설정한 개수까지 동시에 실행되며 선행 결과의 검증·통합 후 다음 작업으로 넘어갑니다. 도구 실행 한도나 작업 경로 충돌로 대기할 수 있으며 대기 이유는 작업 카드에 표시됩니다.
5. 완료되면 **결과 보기**로 결과 작업 폴더, 통합 브랜치와 최종 커밋을 확인합니다. 대표 HTML의 **HTML 미리보기**는 별도 로컬 주소에서 파일과 상대경로 CSS·JS를 엽니다. **전체 산출물 보기**에서 나머지 파일을 확인하고 텍스트 내용을 펼칠 수 있습니다. 원래 체크아웃 대신 이 결과 폴더에 변경을 모읍니다.

화면은 2초마다 작업 그래프, 모델 배정, 실행·검증·통합 상태를 갱신합니다. 작업 노드를 누르면 목표와 검사 기록을 볼 수 있습니다. 실행 중에는 동시 작업 수를 변경하거나 일시정지·재개·취소할 수 있습니다. 조율자 호출이 실패하면 오류를 표시하고 사용자가 다시 시도할 때 새 시도를 만듭니다. 작업자 재작업은 기존 워크플로의 제한된 복구 횟수를 따릅니다.

서버는 `127.0.0.1`에서 실행되며 한 번에 한 업무를 진행합니다. 브라우저 탭을 닫아도 서버 프로세스가 계속 작업을 담당합니다. 실행 기록은 프로젝트의 `.switchbite/workflow`에 저장됩니다. 서버를 교체할 때는 이전 서버가 종료된 뒤 같은 프로젝트에서 `switchbite workflow app --resume RUN_ID --port PORT`로 기존 실행을 이어받습니다. 이전 버전에서 시작해 조율자 정보가 저장되지 않은 실행에는 `--coordinator CANDIDATE_ID`도 지정합니다. 일시정지된 실행은 그대로 열리고, 화면에서 재개할 수 있습니다.

사용 도구 선택은 로컬 사용자 설정에 저장됩니다. 현재 작업은 시작할 때의 선택을 유지하고, 이후 체크박스 변경은 다음 작업에 적용됩니다. 임시로 사용할 수 없는 도구도 저장된 선택을 유지하며, 시작 요청에는 현재 실행 가능한 도구만 포함합니다. CLI의 기존 로그인과 인증 설정으로 각 작업용 새 세션을 실행합니다.

현재 네이티브 실행 대상은 Claude Code·Codex·Cursor Agent·OpenCode·Antigravity입니다. Grok은 설치와 모델을 탐색해 표시하며 실행 연결을 준비 중입니다. 각 CLI의 계정 접근·사용 한도는 실제 실행 결과로 확인합니다.

기존 실행만 보려면 해당 프로젝트에서 `switchbite workflow view RUN_ID`를 사용합니다. 이 모드는 새 업무 입력창 없이 해당 실행의 그래프를 보여줍니다. 포트 변경은 두 명령 모두 `--port PORT`로 지정합니다. Jev는 서버 환경의 `TYPESAFE_API_KEY`를 사용하며, Laya는 기존 `--judge laya --endpoint URL --model NAME` 설정을 사용합니다.

조율자 패널과 작업자 카드에서 최근 출력과 경과 시간을 확인합니다. 그래프 또는 카드를 선택하면 배정 모델·CLI가 실제 보고한 모델·선행 작업·산출물과 시도별 로그가 열립니다. 새 출력이 30초간 없으면 대기 상태, 2분 이상 없으면 주의 상태를 표시합니다. 따라가기를 끄거나 텍스트를 선택해 읽는 동안 위치를 유지하고, 백엔드가 생략한 이전 출력은 잘림 표시로 구분합니다. 출력 복사와 작업 재시도는 해당 카드에서 실행합니다.

상단에는 실제 실행 중인 작업자 수, 현재 작업의 고정 엔진 버전과 다음 작업에 사용할 엔진 준비 상태를 표시합니다. 최신 엔진 자동 연동은 [별도 설정](stackbite-auto-update.ko.md)을 따릅니다. 새 작업 입력 중에도 **완료된 작업 보기**로 이전 결과를 다시 확인할 수 있습니다.

전체 진행 상태는 선택한 출력의 상태와 별도로 표시합니다. 실행 중인 프로세스 없이 차단된 작업이 남아 있으면 **진행 차단 · 작업 확인 필요**로 표시합니다. 단독 `view` 화면은 출력과 상태를 확인하고 실행을 일시정지·재개·취소할 수 있습니다. 현재 작업자를 중단하고 복구 조율을 다시 시작하는 기능은 실행을 담당하는 `app` 화면에서 제공합니다.

시간 초과나 실패 후 재계획 중에도 실패한 시도의 출력은 남습니다. 실행 중인 프로세스가 없을 때 자동 선택은 가장 최근 단계의 출력을 보여줍니다. 조율자 오류와 마지막 조율자 실행 참조도 저장하므로 별도 모니터에서 확인할 수 있습니다. 재계획은 완료된 작업을 유지하면서 조사·구현 범위를 더 작은 하위 작업으로 나눌 수 있습니다.

라우터가 낮은 확신도나 동점으로 배정을 보류하면 현재 조율자가 후보를 검토합니다. 조율자가 고른 후보를 원래 후보 목록과 현재 가용성·작업 조건으로 확인한 뒤 실행을 이어갑니다. 현재 작업 영역의 **조율자**는 계획과 배정을 검토하는 모델이고, 각 카드의 **작업자 배정**은 해당 작업에 선택한 모델과 effort입니다.
