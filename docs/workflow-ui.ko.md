# 로컬 워크플로 화면

`switchbite workflow app`을 실행하고 표시된 주소를 엽니다. 기본 주소는 `http://127.0.0.1:58420/`입니다.

1. 감지된 AI 도구 목록에서 이번 작업에 사용할 도구를 선택합니다. 각 도구의 모델 수와 확인된 연결 상태를 함께 표시합니다. 선택은 자동으로 저장되며, **다시 감지**로 목록을 갱신할 수 있습니다.
2. 커밋이 있는 Git 프로젝트의 절대 경로와 작업 목표, 완료 조건을 입력합니다.
3. **작업 시작**을 누릅니다. 선택 설정에서 허용한 도구의 코디네이터 모델을 고를 수 있습니다. 도구를 하나 이상 선택해야 시작할 수 있습니다. 기존 CLI 로그인으로 새 작업 세션을 실행합니다.
4. 조율자가 작업 계획을 만들고, Jev 또는 설정한 판단기가 허용된 도구에 모델을 배정합니다. 독립 작업은 최대 두 개씩 실행되고 선행 결과의 검증·통합 후 다음 작업으로 넘어갑니다.
5. 완료되면 결과 작업 폴더, 통합 브랜치와 최종 커밋을 확인합니다. 원래 체크아웃 대신 이 결과 폴더에 변경을 모읍니다.

화면은 2초마다 작업 그래프, 모델 배정, 실행·검증·통합 상태를 갱신합니다. 작업 노드를 누르면 목표와 검사 기록을 볼 수 있습니다. 실행 중에는 일시정지·재개·취소할 수 있습니다. 조율자 호출이 실패하면 오류를 표시하고 사용자가 다시 시도할 때 새 시도를 만듭니다. 작업자 재작업은 기존 워크플로의 제한된 복구 횟수를 따릅니다.

서버는 `127.0.0.1`에서 실행되며 한 번에 한 업무를 진행합니다. 브라우저 탭을 닫아도 서버 프로세스가 계속 작업을 담당합니다. 실행 기록은 프로젝트의 `.switchbite/workflow`에 저장됩니다. 서버를 다시 시작하면 입력 화면은 새 세션으로 열리며, 이전 실행은 기존 CLI의 status·continue·view로 확인할 수 있습니다.

사용 도구 선택은 로컬 사용자 설정에 저장됩니다. 현재 작업은 시작할 때의 선택을 유지하고, 이후 체크박스 변경은 다음 작업에 적용됩니다. 임시로 사용할 수 없는 도구도 저장된 선택을 유지하며, 시작 요청에는 현재 실행 가능한 도구만 포함합니다. CLI의 기존 로그인과 인증 설정으로 각 작업용 새 세션을 실행합니다.

현재 네이티브 실행 대상은 Claude Code·Codex·Cursor Agent·OpenCode·Antigravity입니다. Grok은 설치와 모델을 탐색해 표시하며 실행 연결을 준비 중입니다. 각 CLI의 계정 접근·사용 한도는 실제 실행 결과로 확인합니다.

기존 실행만 보려면 해당 프로젝트에서 `switchbite workflow view RUN_ID`를 사용합니다. 이 모드는 새 업무 입력창 없이 해당 실행의 그래프를 보여줍니다. 포트 변경은 두 명령 모두 `--port PORT`로 지정합니다. Jev는 서버 환경의 `TYPESAFE_API_KEY`를 사용하며, Laya는 기존 `--judge laya --endpoint URL --model NAME` 설정을 사용합니다.

**실행 출력**에서 조율자, 작업자 또는 검사 출력을 선택해 최근 내용과 마지막 출력 시각, 경과 시간, 프로세스 상태를 확인할 수 있습니다. 그래프의 작업을 선택하면 해당 작업의 출력도 선택됩니다. 출력이 오래 없다는 표시는 멈춤을 뜻하지 않으며 자동으로 재시작하지 않습니다. 스크롤을 올리거나 따라가기를 끄면 현재 위치를 유지하고, 표시 범위를 넘는 오래된 출력은 생략될 수 있습니다. 재개가 가능한 상태에는 **재개**, 작업 재시도가 가능한 경우에는 현재 시도를 중단하는 **이 작업 중단 후 재시도**가 표시됩니다.
