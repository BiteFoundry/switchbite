# v0.9.0-preview.3

조율자가 정상 반환한 계획을 실행으로 연결하고, CLI 작업이 출력량과 기본 15분 제한 때문에 중단되던 문제를 수정했습니다.

- 조율자와 workflow 도구가 같은 계획 스키마를 사용합니다. 모델 고정값은 `routing`, 필수 기능 ID는 `requirements`, 작업 지침은 `objective`에 전달합니다. 기존 flat 모델 필드와 확인된 레거시 문장 지침도 보존해 정규화합니다.
- Codex 조율자의 구조화된 최종 응답을 회수합니다. 기존 결과 파일도 지원합니다. 잘못된 계획은 노드·필드 진단과 원본 계획을 전달해 한 번 자동 수정합니다.
- 기본 실행 시간 제한을 제거했습니다. 명시적인 `host.timeout_seconds`는 유지하며, 생략 또는 `0`은 CLI 완료나 사용자 취소까지 실행합니다. 이전 웹 버전이 자동 추가한 900초 제한은 비활성 실행의 수동 재개 시 제거합니다.
- stdout과 stderr를 디스크에 보존합니다. 큰 출력은 프로세스를 종료하지 않으며, 완료 판정은 필요한 이벤트를 순차적으로 읽습니다.
- Codex의 사용자 설정을 불러오고 비치명적인 MCP 시작 진단과 실제 실패를 구분합니다. Claude의 파일 편집·빌드·테스트 도구를 연결합니다.
- 각 작업자에게 원래 사용자 목표를 참고 문맥으로 전달합니다. 실행과 쓰기 범위는 개별 작업을 따릅니다.
- 웹은 계획 검증·결과 회수·모델 배정·CLI 실행 오류를 구분합니다. 중단된 실행을 앱 재시작으로 복원하면 사용자 재개를 기다립니다.

기존 작업은 로컬 웹 앱에서 **재개**를 눌러 이어갑니다. 새 작업은 사용할 도구, 경로, 업무를 입력해 시작합니다.
