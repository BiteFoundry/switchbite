# 작업자 캔버스

업무만 입력하면 조율자가 작업과 연결을 만드는 기존 자동 흐름을 사용한다. 직접 구성하려면 **새 작업**에서 프로젝트와 목표를 입력한 뒤 작업 흐름의 **작업자 추가**를 누른다.

## 직접 구성

1. 필요한 만큼 작업자 카드를 추가한다.
2. 카드 안에 **역할**을 자연어로 입력한다. 빈 카드로 남겨도 된다.
3. 카드의 머리를 끌어 배치하고, 오른쪽 출력 연결점을 다른 카드의 왼쪽 입력 연결점에 놓는다. 연결점을 차례로 클릭하거나 탭해도 된다.
4. **이 구성으로 역할 배정**을 누르면 선택한 CLI 조율자가 빈 역할과 실행 세부사항을 채운 뒤 기다린다. 카드 개수·ID·연결·배치는 유지하고, 직접 입력한 역할은 보존한다.
5. **이 계획으로 시작**을 누르면 구성한 순서로 실제 CLI 작업자를 실행한다.

역할별 **저장**을 누르기 전이라도 역할 배정·시작 시 현재 입력을 함께 반영한다. 역할을 모두 직접 입력하고 바로 작업을 시작할 수도 있다. 조율자는 해당 역할의 실행 세부사항을 정리한다.

카드 추가는 작업 정의를 만드는 동작이다. 빈 역할이 있는 미배정 카드는 곧바로 CLI로 실행되지 않는다. 실제 CLI 세션은 구성에 따라 작업 실행 단계에서 생성한다.

## 연결과 배치

- `A → B`는 A의 결과 통합이 끝난 뒤 B를 실행한다는 뜻이다. 선행 작업이 없으면 다른 작업과 독립적으로 실행할 수 있다. 동시 실행 수와 쓰기 경로 예약도 따른다.
- 연결선을 선택한 뒤 **선택한 연결 삭제** 또는 Delete로 제거한다. 순환·중복 연결은 적용하지 않는다.
- **자동 정렬**은 의존 순서대로 카드를 배치한다. 연결이 바뀌면 자동 배치를 따르며, 직접 카드를 옮기면 사용자의 배치를 유지한다. 다시 자동 정렬을 누르면 자동 배치로 돌아간다.
- **화면에 맞춤**, 확대·축소와 캔버스 스크롤로 큰 구성을 탐색한다.
- 드래그한 위치는 격자에 맞추고 카드 겹침을 피한다. 배치는 표시 위치이며 실행 순서를 바꾸려면 연결선을 바꾼다.
- 보조 방식으로 **선행 작업 목록으로 설정**도 사용할 수 있다.

새 작업의 카드와 역할 초안은 프로젝트별로, 실행 중 배치는 실행별로 이 브라우저에 저장한다. 다른 프로젝트에 같은 ID가 있어도 입력이 섞이지 않는다. 역할 자동 배정 중에도 배치는 유지된다.

## 실행 중 수정

아직 시작하지 않은 카드의 역할·연결을 바꾸거나 새 작업자를 추가할 수 있다. 새 미배정 카드는 삭제할 수도 있다. 역할 배정 중 구성이 달라지면 이전 배정 결과를 적용하지 않고 최신 구성으로 다시 판단한다. 직접 입력한 역할과 의존 관계는 후속 재계획에서도 유지한다.

실행·완료된 작업의 정의와 결과는 보존한다. 관찰을 위한 카드 위치 이동은 계속 가능하다. 문제나 새 요구사항은 기존 **조율자에게 전달**로 보낼 수 있다.

## 구현과 검증

기존 Rust 작업 코어·재계획·의존 관계 검증과 SVG 뷰를 확장했다. 새 실행 프레임워크나 브라우저 라이브러리는 추가하지 않았다. 비교 시 [React Flow의 연결점](https://reactflow.dev/learn/customization/handles), [Rete의 자동 배치](https://retejs.org/examples/arrange/), [브라우저 포인터 캡처](https://developer.mozilla.org/en-US/docs/Web/API/Element/setPointerCapture)를 확인했고, 현재 DOM/SVG와 포인터 이벤트를 재사용했다.

2026-10-28 실제 Aside 브라우저에서 카드 추가, 네이티브 포인터 드래그, `worker-1 → worker-2` 연결·삭제, 자동 정렬, 저장 전 역할의 배정 반영, 같은 ID를 쓰는 두 프로젝트의 입력 격리를 확인했다. Codex `gpt-6.1-terra / high`로 실행 ID `run-1793176905950147500-81144`의 **2/2 작업 완료**, `a.txt = Alpha`와 `review.md = PASS`를 확인했다. 원시 기록: `.switchbite/canvas-validation/live-result.json`.

Rust 테스트 316개와 Node 테스트 12개가 통과했다. 데스크톱 캔버스 검토에서 발견한 프로젝트 전환 시 입력 보존 문제를 수정하고 해당 항목의 해결 판정을 받았다. 모바일 픽셀 검증은 완료하지 않았다.
