# 작업 순서 직접 지정

현재 화면은 [작업자 캔버스](worker-canvas.ko.md)의 연결점 드래그를 기본 조작으로 제공한다. 아래 체크박스 방식은 **선행 작업 목록으로 설정**에서 사용할 수 있다.

기본은 업무만 입력하는 흐름이다. 조율자가 작업을 분해하고 의존 관계를 정해 실행한다.

순서를 직접 정하려면 시작 화면에서 **계획을 먼저 확인하고 시작**을 켠다. 조율자는 작업을 나눈 뒤 실행을 기다린다. **작업 흐름 → 작업 순서 직접 지정**을 펼치고 다음 순서로 조작한다.

1. 순서를 바꿀 작업을 고른다. 도표에서 작업을 눌러도 선택된다.
2. 먼저 끝나야 하는 작업을 체크하고 **선행 작업 적용**을 누른다.
3. 도표의 연결을 확인한 뒤 상단의 **이 계획으로 시작**을 누른다.

예를 들어 화면 제작과 API 개발을 병렬로 진행한 뒤 통합하려면 통합 작업을 골라 앞의 두 작업을 체크한다. 선행 작업을 선택하지 않고 적용하면 해당 작업은 독립 실행 대상으로 지정된다. 실제 실행은 동시 실행 수와 쓰기 경로 예약도 함께 따른다.

실행 중에도 아직 시작하지 않은 작업의 관계는 같은 방법으로 바꿀 수 있다. 실행·완료된 작업은 현재 상태를 유지한다. 직접 지정한 관계는 이후 조율자의 재계획과 복구에서도 유지된다. **자동으로 맡기기**를 누르면 해당 작업의 직접 지정을 해제하고 조율자에게 의존 관계 재검토를 요청한다. 일시정지 중이면 재개 후 조율한다.

## 연결 경로

- 시작 요청의 `review_plan: true`는 초기 계획 확정 뒤 작업자 배정 전에 일시정지한다. 기본값은 `false`다.
- 로컬 웹의 `POST /api/dependencies`는 `{run_id, task_id, depends_on}`을 받는다. 배열은 정확히 지정한 선행 작업 목록이며, `null`은 자동 모드 복귀다. 기존 세션·Origin 검사를 사용한다.
- `Workflow::set_dependencies`는 기존 DAG 검증·남은 계획 교체 로직을 재사용한다. 순환 연결, 없는 작업, 실행을 시작한 작업의 변경은 적용하지 않는다. 직접 지정은 `dependency_overrides`와 보고 이력에 저장한다.
- 재계획은 같은 제약을 조율자에게 전달하고, 코어가 최종 계획에도 적용한다. 이 화면에 외부 편집기 라이브러리는 추가하지 않았다.
