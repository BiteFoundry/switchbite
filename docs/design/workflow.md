# 실제 업무 실행 화면

모드: Operate. 대상: `/`, `assets/workflow.html`, `assets/workflow-ui/`.

사용자가 승인한 HTML 목업을 채택한다. 기본 구성과 색·서체·카드·그래프의 형태는 유지한다. 엔진과 작업 조율 로직을 새로 만들지 않고 현재 API를 사용한다.

1. 처음에는 탐색한 CLI 체크박스, 프로젝트 경로, 목표와 조율자 선택을 표시한다. **계획을 먼저 확인하고 시작**은 선택 사항이며 기본은 꺼진 자동 실행이다.
2. 실행하면 계획과 DAG, 작업자별 모델 배정·대기 이유·최근 출력이 갱신된다. 계획 확인을 켜면 **계획 만들기**로 시작하고, 작업 분해 후 작업자 배정 전에 기다린다. **이 계획으로 시작**으로 실행을 이어간다.
3. 카드 또는 그래프 노드를 선택하면 같은 작업의 시도별 출력이 열린다. 로그를 읽거나 선택하는 동안 화면 갱신이 읽기를 방해하지 않는다.
4. 일시정지·재개·취소·실행 중 작업의 재시도와 동시 작업 수 변경을 현재 API에 연결한다.
5. 완료하면 결과 경로·브랜치·커밋과 산출물을 표시하고 HTML은 별도 로컬 미리보기에서 연다.
6. 엔진 상태에는 현재 작업의 고정 버전과 다음 작업용 최신 엔진 준비 상태를 구분한다.

그래프 아래의 **작업 순서 직접 지정**을 펼치면 작업 선택과 **먼저 끝나야 하는 작업** 체크박스가 나온다. 그래프 노드 선택도 같은 작업을 선택한다. 계획 확인 대기에서는 편집 영역을 자동으로 펼친다. **선행 작업 적용**을 누르면 연결이 도표에 반영된다. 아무것도 체크하지 않고 적용하면 독립 실행으로 직접 지정한다. 실제 실행은 동시 실행 수와 쓰기 경로 예약도 따른다.

직접 지정한 관계는 재시작·재계획·복구에서도 유지하며 자동 지정과 구분해 표시한다. **자동으로 맡기기**는 해당 작업의 직접 지정을 해제하고 조율자에게 남은 계획의 관계 재검토를 요청한다. 일시정지 중이면 재개 후 조율한다. 실행 중에도 아직 시작하지 않은 작업은 편집할 수 있다. 이미 시작했거나 완료된 작업은 체크박스와 적용 버튼을 비활성화하고 다른 작업을 선택하도록 안내한다. 자신과 후속 작업은 선행 작업 후보에서 제외하며, 적용 실패 이유와 성공 상태는 편집 영역에 표시한다. 체크박스 초안은 화면 갱신 중 유지한다.

실제 상태는 idle, planning/running, paused, needs-attention, completed, cancelled와 통신 끊김이다. 재연결 중에는 마지막 화면과 입력을 유지한다. 수백 개 모델을 한꺼번에 나열하지 않고 선택한 CLI의 조율자 목록과 현재 배정된 모델을 중심으로 표시한다.

검증: 실제 API를 쓰는 워크플로 회귀 검사, 산출물 경로와 별도 미리보기 검사, 데스크톱·모바일 브라우저에서 입력·그래프·로그·결과 조작을 확인한다.

이번 작업 순서 편집의 실제 검증 범위와 기록은 [작업 순서 직접 지정](../manual-dependencies.ko.md)을 따른다. 실제 Codex 작업 2/2 완료, Rust 309개·UI 10개 테스트와 clippy 통과를 확인했으며 모바일 전용 화면 캡처는 수행하지 않았다.
